# Inspection workflow and Windows 95 interface research

Research and implementation: 3 October 2026. The product decisions below are our interpretation of the sources, not a certification of the app or its AI output. OSHA and HSE guidance informs the workflow; applicable local rules and manufacturer instructions remain specific to the workplace.

## Human analysis

The main surface is a compact photo inspector. An Explorer-style list shows only photographs added in the current window, with a selection highlight, upload/analysis status and a result link. The large preview supports Fit, 100%, 200% and 400% using the local image's natural pixel dimensions. Users can inspect small or ambiguous equipment before submission.

Work activity stays visible below the preview. Required equipment opens a classic dialog; the initial state inventories everything visible. Applying a checklist adds per-person checks without restricting the visible inventory. Custom items, deduplication and the existing 20-item/100-character limits remain. OK applies changes; Cancel and close discard draft edits. Analysis results retain person selection, worn clothing/PPE, carried objects, uncertain identifications, evidence, visibility notes.

## Machinery analysis

A compact assessment brief sits to the left of the photograph on desktop. The main fields are assessment focus, intended task and known machine/model. Material and work environment are disclosed together. All fields may remain blank apart from the default All stages focus; machine identification and operator protection are inferred from the image and supplied context.

Focus choices are All stages, Before use, During operation, Maintenance & isolation and Emergency planning. Focus is saved in the existing operationContext and supplied to inference. It expresses task context; it does not remove other safety phases or guarantee provider emphasis. Input limits keep the combined context below the API's 1,000-character maximum.

The report distinguishes visible hazards from typical risks requiring verification. Operator wearables retain recommended, task-dependent and avoid-during-operation conditions. A phase selector makes precautions easier to scan. Print and JSON reports retain all phases even when the screen is filtered. Confirmation questions remain. Dedicated analysis-limitations, machine-limitations and visual-review panels were removed on 5 October 2026; stored inference metadata and earlier review records remain available in JSON exports.

## Shared behavior and deliberate omissions

- Open several photos or drop them on the preview; each image receives its own saved inspection.
- The current batch updates from Queued through Analyzing to Complete or Analysis failed. The progress bar counts terminal jobs, including failures. Failed results remain available for explicit retry in the result window.
- Poll only inspection IDs submitted in this window. Polling stops on terminal results; intervals scale with batch size. Saved inspection-list queries remain exclusive to History.
- Remove and Clear affect the local photo selection; they do not delete saved inspections.
- On mobile, the photograph precedes the machine brief; the file list sits below the human preview. Analyze and the desktop taskbar remain available.
- No extra accounts, dashboards, subscriptions, advertising panels, recent-history sections, compliance scores or invented detection/confidence overlays were introduced.

The interface is a browser implementation of classic Windows conventions. Rendering and font rasterization depend on the browser and display; the font is a licensed recreation rather than a bundled Microsoft asset. No service pricing or provider behavior changed in this redesign.

## Validation

Browser verification covers result-pane-only scrolling, settings Apply/OK/Cancel and validation, time-zone previews, adjacent history counts, distinct layouts, image selection/zoom/removal, dialog apply/cancel/Escape, checklist submission, task-focus submission, disclosure of machine details, phase filtering and printing, batch status transitions/failure messages, stopping terminal polling, window state preservation, history-only list requests and 390px layouts. UI/provider responses in these tests are explicitly labelled fixtures; the tests consume no Gemini quota and do not measure inference accuracy.

## Settings redesign and result windows — 5 October 2026

The previous settings window devoted most of its space to service explanations and left the two editable preferences below them. Research focused on the smallest useful properties dialog, how edits commit or cancel, valid-choice controls, and fitting the window to its actual content. The following are primary Microsoft references. The surviving 2007 and Windows 7 guidelines inform interaction decisions; they are not Windows 95 pixel specifications. The existing Windows 95 palette, bevels, pixel icons, font and window manager supply the visual theme.

Gemini's configured state is read-only and does not promise a successful API call. Service access still checks when a photograph is analyzed; opening Settings or checking configuration consumes no AI quota. No subscription, API-key entry field in the browser, account controls or extra appearance settings were added.

Both result applications now use a fixed document frame. The source photograph, document commands, image metadata and provenance remain visible. The keyboard-focusable Safety analysis region alone scrolls, including task context and processing/failure messages. On narrow screens the photograph occupies the upper portion and the analysis occupies the remaining height. Printing removes the scroll constraint so all precautions remain printable. Removed sections no longer render; the underlying saved result is preserved.

History adds Machinery immediately beside People. An analyzed empty machine list shows zero; pending inspections and older results without a machine assessment show an em dash. Counts represent identified entities in each image, rather than a safety score.

Fixture-backed browser checks cover desktop and 390px result scrolling, a fixed photograph and toolbar, removal of both panels, preserved print output, two-machine history counts, draft cancellation without writes, valid and invalid names, Apply/OK persistence, clock changes after Apply, failure handling, and the collapsed/expanded settings layouts. No live Gemini requests are needed for these checks.
