# Architecture

Browser → same-origin proxy → Next.js / NestJS → PostgreSQL + private image storage.

The worker reads the saved photo, checklist and optional activity/machine context, then calls authenticated FastAPI inference. Inference bounds provider image resolution, calls Gemini with a server-only key and structured output, and validates inventories and structured machinery guidance. The worker validates dimensions, person identifiers and checklist coverage before committing results. There is no detector or fixture fallback.

Each person has a positional description, equipment with name/category/status/evidence, required-item checks and visibility notes. PPE, clothing and carried objects are distinguished. Uncertainty is preserved. No invented coordinates or confidence percentages are returned.

Machinery is automatically assessed in the same request, including scenes without people. Machine identification certainty, visible versus typical hazards, phased precautions, conditional operator PPE/wearables and missing-context questions remain separate from observed person inventories. Pydantic and shared Zod contracts enforce limits, unique machine IDs and reject unconditional glove recommendations for flagged rotating-machine entanglement. Gemini receives a simplified JSON schema; full local constraints remain enforced after inference. New results use safety-v2; machinery is optional only for historical result compatibility. Requirements JSON stores context without another database migration.

Persistent jobs use transactional SKIP LOCKED claiming and a single-instance advisory lock. Provider timeout: 75 seconds; worker timeout: 95 seconds; abandoned lease: two minutes. At most three attempts are allowed. Failure awaits explicit retry.

Reanalysis copies the stored bytes into a new inspection/job. Reviews append observations and notes without changing the original result. Photo deletion retains evidence. SSE validates sessions and publishes workspace changes; pending inspections also poll.

The client desktop lives in the shared root layout so application URL changes preserve open windows and React form state. A window registry tracks active/stacking order, minimize/maximize state and positions. Each application retains its own upload state. A shared photo-intake component provides object-URL image previews, natural-size zoom, file selection and current-batch progress. Human analysis uses an Explorer-style list/preview and a separate draft/apply PPE requirements dialog. Machinery analysis uses a task-focused brief next to its preview, with disclosed material/environment fields. Human analysis sends selected required equipment; Machinery analysis sends an empty checklist and combines assessment focus, task/model/material/environment into the existing bounded operationContext string. Per-ID TanStack queries track submitted jobs, scale polling intervals with batch size and stop at terminal states. They share the inspection-detail query cache. The machinery report can filter precautions on screen while printing and JSON retain all phases. Saved inspection lists are fetched and displayed only by History; the analysis applications no longer poll recent records. Window title controls and taskbar operate on the registry; results remain normal URL-addressable inspections. The desktop clock uses browser time and the saved IANA workspace time zone. SVG cursors, pixel icons and the licensed WIN95FA recreation font are local assets.

Opening the app creates an anonymous 24-hour HttpOnly session. Tokens are hashed. Mutations require the same origin and session CSRF token. Queries verify facility boundaries. No admin/officer/viewer identities are created or authenticated.

Legacy schema and REAL/DEMO results remain for compatibility. The retired controllers, simulator, model adapter and fixture inference are removed. The frontend labels older analyses explicitly.

Result windows contain a single scrollable Safety analysis region; source photos, commands, metadata and provenance stay fixed. Printing restores normal document flow. Analysis-limitations and visual-review controls no longer render; stored analysis warnings, machinery limitations and historic review records remain in the API/export format. History lists both person and machinery counts, preserving unknown counts for legacy or pending results.

Settings uses a dedicated properties component with local drafts and a saved baseline. OK applies and closes; Apply commits without closing; Cancel/Escape/close discard unapplied edits. PATCH uses the existing anonymous session and CSRF token. Successful changes invalidate the auth query so the desktop clock and timestamps use the saved time zone. The time-zone preview uses the draft independently. Service details are read-only and initially collapsed.
